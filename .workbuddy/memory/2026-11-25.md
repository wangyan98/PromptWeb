## Danbooru 词库导入单词本（双来源兼容）
- 需求：把 `dataset/Danbooru词库-全量JSON(32.7万条).json`（327,687 条 `{name,category,cn_name,post_count}`）导入单词本；原有词来自语句提取。用户选择：统一并入同一个单词本 + 来源筛选；卡片不显示 category/post_count；排序改为归一化综合权重。
- 权重公式（用户指定）：`0.5*(x-min)/(max-min) + 0.5*(y-min)/(max-min)`；x=按 word_en 的语句词行数，y=post_count（无 Danbooru 记录取 0）。min/max 在全库统计，不随搜索/来源筛选变化；缺失项取各自 min（贡献 0）。权重只用于 ORDER BY，不展示。
- 后端改动：
  - 新 migration `c7a91b3e5d24_add_word_source_and_danbooru_fields.py`：`prompt_id/statement_id` 改可空，加 `source/category/post_count`，加 word_en/prompt_id/statement_id 索引 + `WHERE source='danbooru'` 的部分唯一索引（幂等导入）。
  - `PromptWord` 模型/schema 同步；新增 `POST /api/words/import` 批量导入（ON CONFLICT DO NOTHING）。
  - `/api/words/global` 新增 `source=all|statement|danbooru`，返回 `source/sources`；`prompt_ids` 过滤 NULL；按综合权重降序。
- 前端改动：`GlobalWordItem` 加 source/sources；单词本工具栏加来源切换；Danbooru 卡片隐藏次数行（不显示 post_count）。
- 导入脚本：`skills/prompt-analyzer/scripts/import_danbooru.py`，块式流式解析 JSON 数组（不会整文件加载），1000 条/批 POST，支持 `--dry-run/--limit`。全量导入 34 秒，零错误。
- 结果：Danbooru 327,687 行；原语句词 44,184 行/17,520 词；两来源重叠 1,436 词；单词本共 343,771 词。Top 排序示例：highres(0.5368)、1girl(0.5265)、cinematic(0.5)、solo(0.4346)、masterpiece(0.3861)——两种来源混合，与 SQL 手算一致。
- 性能：`/api/words/global` 首页约 1.3s（冷）/0.3-0.9s（后续、搜索、深页）；`vue-tsc` + `vite build` 通过（build 约 3.5 分钟，默认 120s 超时会被杀，需显式加长 timeout）。
- 运维注意：容器停止过久后 postgres 健康检查会假阴性（启动需 ~13s），用 `docker compose up -d --no-deps backend` 启动即可；`alembic upgrade head` 已执行。
